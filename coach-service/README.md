# 私人象棋教练：首版实现

此服务独立于 App 运行。每分钟检查持久化教学安排，在约定的一个小时窗口内选择到期材料、调用模型备课、保存课程，然后尝试发送 APNs。手机和 Mac 连接同一服务，读取同一课与学习记录。它是**单个学生、单进程、单副本**服务，不是多租户平台。

## 已实现

- App 默认进入教练课堂，可随时返回原棋谱界面；只在学生点击上传后发送预览中的局面、材料出处、目标和笔记副本。不会自动上传整个棋谱库。
- 每个材料有稳定 ID、原始来源快照、学习目标、复习间隔和到期时间。当前导入单位为一个教材局面，支持多个局面。原始笔记不会被覆盖。
- 模型准备问题、提示、讲解；学生先写思路，再揭示讲解，也可继续追问。追问及回答持久化。所有生成解释标明尚未核验，不用于自动判错。
- 按学生自评安排重复复习：首次独立回忆 1 天，随后 3 天，再按两倍增长（上限 60 天）；提示后缩短到 1–3 天；需要再学为 1 天；不确定保留成功历史并短期重测。这是可解释的初始调度规则，不是已拟合的个人遗忘模型。
- 看过提示/讲解不算独立回忆。未参与不会产生失败记录。暂缓只推迟该材料；暂停停止主动备课与通知。
- 每个本地日最多一堂新课，每台设备最多一次通知尝试。模型请求（包含追问与失败重试）有每日上限；自动备课重试至少间隔 15 分钟。尚未备课、没有未完成课程、仍在当天联系窗口之前或之内且有到期材料时，为主动备课保留一次请求额度；额度耗尽导致顺延会显示原因。
- 多设备共享准备好的课程；“同步本课草稿”上传当前文字和提示记录。显式取回另一设备草稿，冲突返回 409，保留本地文字。作答 ID 幂等，同课只能完成一次。
- JSON 原子替换和 fsync；外部调用前预留额度和通知记录。损坏的存档拒绝启动，不默默变为空库。写盘失败后停止操作，等待修复并重启。
- 凭据保存在客户端独立、按服务地址区分的本机 Keychain；不复用聊天凭据。客户端拒绝远程明文 HTTP 和重定向。启动断网时自动使用已保存配置退避重连（30 秒起、最多 5 分钟），不会把凭据发送到尚未保存的编辑地址。教学设置使用独立版本号，未保存编辑保留原版本；草稿或设备状态更新不会误报设置冲突，也不会随后台刷新覆盖其他设备的暂停操作。
- 服务端清除操作删除教材、课程、草稿、讨论、答题、设备和推送记录并暂停；当日用量计数保留，避免通过清除绕过限额。设备同步到清除事件后会撤销本机通知同意，并提示重新开启，避免静默重新登记已删除的设备。

## 本地启动与上线准备

需要 Node 20+。无需 npm 依赖。

1. 将 `.env.example` 复制为 `.env`，填写至少 32 字符的随机 `COACH_TOKEN`。该凭据在自己的各台设备上共用。
2. 填入模型的完整 Chat Completions URL、密钥、模型名。Azure 可使用带 deployment 与 api-version 的地址，并设置 `COACH_LLM_AUTH=api-key`。不读取或转用本机 Claude/ChatGPT 订阅登录凭据。
3. 在此目录运行 `node --env-file=.env server.mjs`。默认仅监听回环地址 9220。
4. App 的教练设置中输入服务根地址和凭据。选择教材局面，核对预览后上传，保存学习目标、联系时间和启用状态。
5. 服务只在约定时段备课。测试时可把联系时间设为当前本地小时，等待下一个分钟检查；不要将这个测试设置误当成正式教学安排。

跨设备/长期使用需部署到常驻主机并配置 HTTPS。Dockerfile 可作为构建起点，尚未执行云端部署。必须挂持久卷到 `/data`，确保 node 用户可写；只能运行一个副本，禁止滚动更新同时挂同一数据卷。容器/主机退出后靠进程管理器重新启动。锁恢复只支持同一 PID 命名空间或单容器重启，不支持多容器共享卷。

停机错过联系窗口时不在夜间补发；下一次窗口继续。准备课程失败时课堂显示状态，不会发一条没有课程的邀请。模型未配置时可以保存材料，但不会伪造课程。

## APNs 配置边界

已写好发送端、设备 token 注册回调、通知点击回到课堂的接线，但**没有启用线上 Apple capability，也没有真实推送验证**。

- Apple Developer 的 App ID 需要启用 Push Notifications，并刷新匹配的 provisioning profile。
- 正式工程签名配置未修改；需要为 iOS 配置 `aps-environment`，macOS 配置相应的 `com.apple.developer.aps-environment`。应与开发/发行证书及 profile 匹配，不在代码里写个人 Team ID。
- APNs provider token 缓存复用 45 分钟，不为每台设备重新签发，参照 [Apple token 连接说明](https://developer.apple.com/documentation/usernotifications/establishing-a-token-based-connection-to-apns)。
- 服务需要 `.p8`、Key ID、Team ID 与 topic。开发安装选择 sandbox；TestFlight/正式发行选择 production。当前一个服务实例仅对应一个 APNs 环境，不混用开发和发行设备。
- App 设置里开启此设备通知后，才请求系统权限与注册。注册失败会显示具体错误。
- 通知只包含通用邀请与课程 ID，不在锁屏展示笔记和回答。App 始终从已配置的服务获取内容，推送不能指定任意服务地址。
- APNs 200 只记为 `accepted-by-apns`，不等于设备送达。超时记 unknown，避免模糊结果导致重复提醒。崩溃前预留的推送记录也不自动重发；课堂保留课程。

参考：[Apple APNs 请求格式](https://developer.apple.com/documentation/usernotifications/sending-notification-requests-to-apns)、[注册设备](https://developer.apple.com/documentation/usernotifications/registering-your-app-with-apns)。

## API

所有接口要求 `Authorization: Bearer <COACH_TOKEN>`；无公开数据接口，不记录请求内容/凭据。

| 接口 | 用途 |
| --- | --- |
| GET /v1/coach | 课程、材料、历史、草稿与服务能力 |
| POST /v1/preferences | 使用 snapshot.preferencesRevision 作为请求 revision，条件更新目标、联系窗口、时长、请求上限、暂停 |
| POST /v1/materials | 幂等新增不可变教材快照 |
| POST /v1/progress | 草稿 revision 条件更新 |
| POST /v1/questions | 基于本课与材料追问，共享每日模型额度 |
| POST /v1/attempts | 幂等记录思路与自评，安排下次复习 |
| POST /v1/defer | 暂缓当前课，不记录失败 |
| POST /v1/devices | 注册或替换本设备 token |
| POST /v1/devices/remove | 撤销设备 token |
| POST /v1/reset | revision + 明确确认后清除教练记录 |

## 验证与已知边界

运行 `npm test`。测试使用可控时钟、临时文件和假模型/推送，覆盖多日复习、停机恢复、幂等、冲突、限额、失败、未回应与 HTTP 鉴权；不是线上模型或真实 APNs 的证明。

目前是第一条可运行链路，仍需后续工作：

- PDF/OCR、整章自动拆解、章节前置知识与系统课程规划尚未实现；本版从已有结构化局面和笔记开始。
- 云端未接 Pikafish/规则工具，FEN 检查仅验证格式，不能证明合法性或棋理。原棋谱的引擎能力保持可用，但尚未接入云端备课。不能宣称生成解释正确。
- 课堂棋盘目前只展示来源局面，尚无教练逐步控制演示、变式训练或自动着法评判。复习证据是回忆与学生自评，不能宣称迁移或棋力提升。
- 尚未使用真实模型完成多日教学质量试验；课时数只是计划，不是自动测得的实际学习时长。每日请求上限并不等价于金额上限。
- 草稿需要显式同步；离线不能提交反馈，也不会伪装提交成功。本地草稿在连接成功后恢复；服务记录用于跨设备接续。
- 单用户共享服务凭据不提供细粒度用户权限。部署前还需选定常驻主机、HTTPS、备份/保留策略、模型与费用上限。
