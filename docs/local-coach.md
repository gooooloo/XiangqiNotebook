# 本地私人教练

不再部署 coach-service，不需要服务地址、独立密钥、Azure 模型或 APNs。
旧服务代码已移除；没有远程删除旧数据的操作。如曾自行部署旧服务，需要先自行导出数据，本版本不自动访问旧服务。旧 Keychain 凭据不会被使用。

## 使用

1. 在棋谱中选择教材笔记，将当前局面加入教练学习范围。副本保存本机，原始笔记不改动。也可先试学本地诊断课，稍后 review；试学不批准长期计划或发送提醒。
2. 教练提出目标、材料、每天时长、模型请求上限及提醒安排。review 后采用具体版本。
3. 打开课堂直接进入当日课程。在批准范围内每天安排一节，讲解、理解检查、自评和复习由教练推进，不必每天再批准。
4. 模型使用「模型设置（与问棋共用）」中的现有渠道；只发送相关教材副本和必要学习上下文。备课先提供本地笔记练习，再异步补充模型讲解，最多等待 45 秒且可停止；后台同步不禁用输入。没有模型或额度耗尽时仍可继续。
5. 如需提醒，在计划中指定「此设备」，review 该版本，并允许系统本地通知。按下一到期日安排最多四次提醒（到期日及之后第 1、3、6 天）；今天未学且未过提醒时间也会安排。后台定时检查或自动启动不延长提醒期限，进入前台/课堂时才更新交互基准，长期不使用不会无限催促。这是明确展示的提醒策略，可通过暂停或关闭提醒撤销。
6. Mac 可选择登录后启动，关窗口后进程继续；真正退出或睡眠时不备课。iOS 不保证后台运行或自动打开前台。通知由系统调度，送达受权限和专注模式影响。

## 数据与同步

- 本机 `Application Support/XiangqiNotebook/Coach/v1` 保存权威记录和待同步文件；iCloud `Documents/XiangqiNotebook/Coach/v1` 保存相同不可变记录。
- 每个事件独立文件，UUID 标识操作，文件名为内容 SHA-256。相同操作去重；同 ID 不同内容均保留，标为冲突，不选较新文件覆盖。文件写入经过 NSFileCoordinator 和原子写；未下载的占位文件不尝试覆盖。普通学习记录身份冲突只影响保守复习，不撤销有效教学授权；审批/计划身份冲突则停止授权，避免误用旧范围。
- 计划持久化最初的编码字节（后续解码/新字段不改变身份），有内容哈希、父审批 ID；批准绑定精确版本。草稿不生效，修改后需重新 review。非法内容的审批会被标记并忽略，不阻断其他有效计划；缺依赖的审批暂时停止授权，等待同步补齐。审批分叉只沿有效范围交集行动，限制取严格者；用户选择一个分支会创建新的合并版本。
- 更正引用原事件，不删除原始回答。因果后继覆盖派生视图；并发矛盾全部保留，暂保守复习。用户行为、自评、AI 解释是不同来源，不能宣称客观掌握。
- 复习规则版本 `coach-review-v1`：独立回忆按 1、2、4…天递增，最多 30 天；提示/不确定/需重学回到 1 天；按计划时区的日历日到期，不要求等到上次作答的精确时刻；同一日历日不算第二次间隔巩固；次日早晨复习即使不足 20 小时也计入。时钟明显偏未来的记录不用于推迟复习；矛盾更正或离线双答只让相关材料从该次学习起按一天重新安排，后续独立回忆仍可推进，其他材料不受影响。
- 本地内存索引只解码新文件；计划图及复习到期日由快照缓存，按键不重复构建审批图。尚未下载、格式损坏或未知 schema 均显示同步不完整，不清理文件或推定数据不存在；无共享文件锁，不保证跨设备实时一致。
- 首个 iCloud 账号与本机教练数据绑定；切换账号不自动把旧资料上传新账号。本机仍可使用，需专门迁移后才允许新账号同步。
- 草稿本机防抖保存（300 毫秒；后台及退出立即保存），明确保存或切入后台时追加同步副本；其他设备的草稿由用户选择载入，不覆盖当前输入。

## 边界与验证

模型请求前先记用量，失败和重试也计数。离线多设备下无法提供全局硬额度，也不能保证旧设备立即取消通知；默认只有计划指定的设备排系统提醒。模型输出不自动成为审批、评分或事实。

首版从选定的教材局面/笔记教学。书籍 OCR、整本书自动解析、经过引擎验证的自动判题及迁移题不包含在本次改造；具体着法讲解标明未核验。正在作答时钉住题目版本，另一设备的课程或模型补充不切换当前题目。过早生成的重复课不作为后续复习课复用；修改提醒设置不清除当前答案。不是单凭自评证明棋力提升。

测试覆盖离线合并、审批分叉/暂停、缺失审批祖先、精确版本审批、草稿保留、更正冲突、短期重复、提醒归属、模型失败及课堂截图。iCloud 跨真机同步、系统通知送达和各订阅渠道需要实机验收，模拟测试不能替代。
